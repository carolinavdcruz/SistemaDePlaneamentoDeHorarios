    \section{Objetivo do Documento}

    O presente documento descreve os procedimentos necessários para instalação, configuração, execução e validação do projeto \textit{Sistema de Planeamento de Horários}, permitindo ao arguente instalar, executar e validar os principais fluxos funcionais da solução final.

    \section{Repositório do Projeto}

    O projeto encontra-se disponível no seguinte repositório:

    \begin{quote}
        \url{https://github.com/carolinavdcruz/SistemaDePlaneamentoDeHorarios.git}
    \end{quote}

    Para obter uma cópia local do projeto, poderá ser utilizado o comando:

    \begin{verbatim}
        git clone https://github.com/carolinavdcruz/SistemaDePlaneamentoDeHorarios.git
    \end{verbatim}
    \section{Requisitos de Software}

    Para executar corretamente o projeto, é necessário garantir a instalação dos seguintes componentes:

    \begin{itemize}
        \item Java Development Kit (JDK), versão 21 ou superior;
        \item Android Studio, com Android SDK, Emulator e Platform Tools;
        \item PostgreSQL, com uma base de dados local acessível;
        \item Gradle Wrapper incluído no projeto;
        \item acesso a uma conta Google válida para validação da integração com Google Calendar;
        \item acesso a uma conta de email configurada no backend, caso se pretendam validar notificações por correio eletrónico.
    \end{itemize}

    A verificação das versões instaladas pode ser feita, por exemplo, com os seguintes comandos:

    \begin{verbatim}
        java --version
        psql --version
    \end{verbatim}

    Para a execução da aplicação Android, recomenda-se a utilização de um emulador com configuração semelhante a:

    \begin{itemize}
        \item dispositivo: Pixel 6;
        \item versão Android: API 34 ou equivalente.
    \end{itemize}

    \section{Configuração da Base de Dados}

    O backend encontra-se configurado para utilizar uma base de dados PostgreSQL local. Antes de iniciar a aplicação, deverá existir uma base de dados com o nome \texttt{sph}.

    Os parâmetros utilizados são os seguintes:

    \begin{itemize}
        \item base de dados: \texttt{sph}
        \item utilizador: \texttt{postgres}
        \item palavra-passe: \texttt{postgres}
        \item porto: \texttt{5432}
    \end{itemize}

    Assim, antes de arrancar o backend, deverá ser criada uma base de dados com o nome \texttt{sph} no PostgreSQL local.

    A estrutura de tabelas necessária ao funcionamento do sistema é criada automaticamente pelo backend no arranque através da camada de persistência da aplicação.

    \section{Execução do Backend}

    Após a configuração da base de dados, o backend pode ser iniciado a partir da pasta \texttt{backend} com o comando:

    \begin{verbatim}
        ./gradlew run
    \end{verbatim}

    O servidor ficará disponível localmente no porto \texttt{8080}.

    \section{Execução da Aplicação Android}

    A aplicação Android deve ser aberta no Android Studio a partir da pasta:

    \begin{verbatim}
        frontend_AndroidApp
    \end{verbatim}

    Depois disso, deverá ser iniciado um emulador Android ou ligado um dispositivo físico compatível, seguindo-se a execução normal da aplicação a partir do Android Studio.

    Durante a execução, a aplicação comunica com o backend local através da API REST.

    Para que a aplicação funcione corretamente, o backend deverá já encontrar-se em execução no momento em que a app é iniciada.

    \section{Integração com Google Calendar}

    O sistema suporta integração com o Google Calendar no contexto do professor. Após a aceitação e persistência de um horário, os eventos correspondentes podem ser registados no calendário Google autenticado do professor.

    Para esta funcionalidade, deverá estar configurada uma conta Google válida e devidamente autenticada no dispositivo ou emulador utilizado na demonstração.

    \section{Arquitetura Geral da Solução}

    A arquitetura geral da solução pode ser resumida da seguinte forma:

    \begin{center}
        Android App $\rightarrow$ API REST (Ktor) $\rightarrow$ PostgreSQL
    \end{center}

    O frontend Android é responsável pela interação com o utilizador, enquanto o backend centraliza a lógica de negócio, a persistência remota de dados, a gestão das aulas, o histórico, o controlo de presenças, o envio de notificações e a integração com serviços externos.

    O funcionamento principal do sistema segue estes passos:

    \begin{enumerate}
        \item o utilizador interage com a aplicação Android;
        \item a aplicação comunica com o backend através da API REST;
        \item o backend processa os pedidos e aplica a lógica necessária;
        \item os dados são persistidos e consultados na base de dados PostgreSQL;
        \item no caso do professor, o horário aceite pode ainda ser integrado no Google Calendar.
    \end{enumerate}

    \section{Funcionalidades a Verificar}

    Durante a avaliação do projeto, recomenda-se a verificação das seguintes funcionalidades:

    \begin{itemize}
        \item registo e autenticação de professores e alunos;
        \item associação de alunos a professores;
        \item definição de disponibilidades semanais;
        \item definição de restrições do professor;
        \item definição da carga horária semanal pretendida pelo aluno;
        \item geração de propostas de horário semanal;
        \item aceitação e gravação de aulas com datas reais;
        \item recorrência semanal de aulas;
        \item consulta de aulas gravadas e histórico;
        \item marcação de presenças;
        \item cancelamento e remarcação de aulas;
        \item envio de notificações por email;
        \item integração com Google Calendar;
        \item persistência remota em PostgreSQL.
    \end{itemize}

    \section{Observações Finais}

    Caso seja necessário repetir demonstrações a partir de um estado controlado, recomenda-se validar previamente a base de dados e os dados persistidos de utilizadores, disponibilidades, restrições e aulas.
