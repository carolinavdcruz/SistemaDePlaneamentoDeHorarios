    \section{Objetivo do Documento}

    O presente documento tem como objetivo descrever a forma de instalação, configuração, execução e verificação do projeto \textit{Sistema de Planeamento de Horários}, permitindo ao arguente testar os principais fluxos funcionais da aplicação.

    \section{Repositório do Projeto}

    O projeto encontra-se disponível no seguinte repositório:

    \begin{quote}
        \url{https://github.com/carolinavdcruz/SistemaDePlaneamentoDeHorarios.git}
    \end{quote}

    Para obter uma cópia local do projeto, poderá ser utilizado o comando:

    \begin{verbatim}
git clone https://github.com/carolinavdcruz/SistemaDePlaneamentoDeHorarios.git
    \end{verbatim}

    \section{Requisitos de Software}

    Para executar corretamente o projeto, é necessário garantir a instalação dos seguintes componentes:

    \begin{itemize}
        \item Java Development Kit (JDK), versão 21 ou superior;
        \item Android Studio, com Android SDK, Emulator e Platform Tools;
        \item PostgreSQL, com uma base de dados local acessível;
        \item Gradle Wrapper incluído no projeto, não sendo necessária instalação manual de Gradle.
    \end{itemize}

    A verificação das versões instaladas pode ser feita, por exemplo, com os seguintes comandos:

    \begin{verbatim}
java --version
psql --version
    \end{verbatim}

    Para a execução da aplicação Android, recomenda-se a utilização de um emulador com configuração semelhante a:

    \begin{itemize}
        \item dispositivo: Pixel 6;
        \item versão Android: API 34 ou equivalente.
    \end{itemize}

    \section{Configuração da Base de Dados}

    O backend encontra-se configurado para utilizar uma base de dados PostgreSQL local com os seguintes parâmetros:

    \begin{itemize}
        \item base de dados: \texttt{sph}
        \item utilizador: \texttt{postgres}
        \item palavra-passe: \texttt{postgres}
        \item porto: \texttt{5432}
    \end{itemize}

    Assim, antes de arrancar o backend, deverá ser criada uma base de dados com o nome \texttt{sph} no PostgreSQL local.

    A estrutura de tabelas necessária ao funcionamento do sistema é criada automaticamente pelo backend no arranque através da camada de persistência da aplicação, pelo que não é necessária a execução manual de \textit{scripts SQL} para utilização da versão beta.

    \section{Execução do Backend}

    Após a criação da base de dados, o backend pode ser iniciado a partir da pasta \texttt{backend} com o comando:

    \begin{verbatim}
./gradlew run
    \end{verbatim}

    O servidor ficará disponível localmente no porto \texttt{8080}.

    \section{Execução da Aplicação Android}

    A aplicação Android deve ser aberta no Android Studio a partir da pasta:

    \begin{verbatim}
frontend_AndroidApp
    \end{verbatim}

    Depois disso, deverá ser iniciado um emulador Android ou ligado um dispositivo físico compatível, seguindo-se a execução normal da aplicação a partir do Android Studio.

    Durante o desenvolvimento, a aplicação encontra-se configurada para comunicar com o backend local através do endereço apropriado ao emulador Android.

    Para que a aplicação funcione corretamente, o backend deverá já encontrar-se em execução no momento em que a app é iniciada.

    \section{Integração com Google Calendar}

    A versão beta inclui integração com o Google Calendar no contexto do professor. Após a aceitação de uma proposta de horário, a aplicação permite autenticar o utilizador com uma conta Google e registar automaticamente as sessões no respetivo calendário.

    Para esta funcionalidade, deverá estar presente no projeto Android o ficheiro de configuração Google incluído na aplicação, bem como uma conta Google válida para autenticação no dispositivo ou emulador. A inserção das sessões no calendário é efetuada apenas após a aceitação da proposta de horário pelo professor.

    A integração com o Google Calendar é opcional para a navegação geral da aplicação, mas faz parte dos fluxos principais que podem ser demonstrados na apresentação.

    \section{Fluxo Geral do Sistema}

    A arquitetura geral da solução pode ser resumida da seguinte forma:

    \begin{center}
        Android App $\rightarrow$ API REST (Ktor) $\rightarrow$ PostgreSQL
    \end{center}

    O funcionamento principal do sistema segue estes passos:

    \begin{enumerate}
        \item o utilizador interage com a aplicação Android;
        \item a aplicação comunica com o backend através da API REST;
        \item o backend processa os pedidos e aplica a lógica necessária;
        \item os dados são persistidos e consultados na base de dados PostgreSQL;
        \item no caso do professor, o horário aceite pode ainda ser integrado no Google Calendar.
    \end{enumerate}

    \section{Funcionalidades a Verificar}

    Durante a avaliação da versão beta, recomenda-se a verificação das seguintes funcionalidades:

    \begin{itemize}
        \item registo de professores e alunos;
        \item autenticação de utilizadores;
        \item gestão de sessão e adaptação da interface ao perfil autenticado;
        \item associação de aluno a professor e respetiva troca;
        \item definição de disponibilidades, incluindo múltiplos intervalos por dia;
        \item definição de restrições do professor;
        \item construção de propostas de horário;
        \item visualização do horário semanal;
        \item aceitação do horário;
        \item integração com Google Calendar;
        \item persistência remota em PostgreSQL.
    \end{itemize}

    \section{Casos de Teste Recomendados ao Arguente}

    \subsection*{Caso 1 -- Registo e Login}

    \begin{enumerate}
        \item registar um professor ou aluno na aplicação;
        \item efetuar login com credenciais válidas;
        \item confirmar o acesso ao fluxo correspondente ao perfil autenticado.
    \end{enumerate}

    \subsection*{Caso 2 -- Associação entre Aluno e Professor}

    \begin{enumerate}
        \item autenticar um aluno;
        \item selecionar um professor da lista disponível;
        \item confirmar que o professor associado passa a estar visível no perfil do aluno.
    \end{enumerate}

    \subsection*{Caso 3 -- Definição de Disponibilidades}

    \begin{enumerate}
        \item inserir disponibilidade para professor ou aluno;
        \item adicionar mais do que um intervalo no mesmo dia;
        \item guardar e confirmar a persistência dos dados.
    \end{enumerate}

    \subsection*{Caso 4 -- Definição de Restrições e Construção de Horário}

    \begin{enumerate}
        \item autenticar um professor;
        \item definir restrições de agendamento;
        \item construir uma proposta de horário;
        \item confirmar a apresentação organizada das sessões criadas.
    \end{enumerate}

    \subsection*{Caso 5 -- Aceitação do Horário e Google Calendar}

    \begin{enumerate}
        \item aceitar uma proposta de horário criada;
        \item autenticar uma conta Google, se necessário;
        \item confirmar que as sessões são adicionadas ao Google Calendar do professor.
    \end{enumerate}

    \section{Observações Finais}

    A documentação complementar do projeto encontra-se disponível na pasta \texttt{docs/}, incluindo o relatório beta, notas técnicas, apontamentos de arquitetura e material de apoio ao desenvolvimento.

    Caso seja necessário testar a aplicação a partir de um estado limpo, recomenda-se remover ou recriar a base de dados \texttt{sph} antes de iniciar novamente o backend, permitindo que as tabelas sejam criadas de novo automaticamente.
